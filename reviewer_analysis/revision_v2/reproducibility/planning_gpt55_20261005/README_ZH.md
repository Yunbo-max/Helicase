# GPT-5.5 两组真实规划对照：80 次执行结果

2026-10-05 完成。Q61–Q80，Helicase（`full`）与保留 KG 的 Uniform-planning（`uniform`），每组每题两次独立执行，共 **80 次**。四次技术试运行不计入下表。全部报告及部分完成记录保留；没有重跑成功的研究任务，也没有复用旧报告作为新运行。

## 答案指标

| 方法（各 40 次） | Answer Precision | Answer Recall | Answer F1 |
|---|---:|---:|---:|
| Helicase：调用与工具上限控制版 | 23.56% | 37.19% | **26.75%** |
| Uniform-planning KG | 17.37% | 33.44% | **21.21%** |

Helicase − Uniform 的 F1 差为 **+5.54 个百分点**。先平均每题两次 F1，再对 20 道题的配对差做 10,000 次 bootstrap，95% CI 为 **[−3.08, +13.71] 个百分点**，包含 0。**本批均值较高，但不能据此声称显著优势或充分稳定性。** 本轮只比较这两个方法，不是旧七方法排行榜的重新排序。

| 方法 | 第一次运行的宏平均 F1 | 第二次运行的宏平均 F1 | 两次均值的样本 SD |
|---|---:|---:|---:|
| Helicase | 34.41% | 19.10% | 10.83 个百分点 |
| Uniform-planning KG | 16.52% | 25.90% | 6.63 个百分点 |

两个重复的 SD 很不稳定；40 个题次没有当成 40 道独立问题。Precision、Recall 和 F1 分别逐次、逐题宏平均，不能用平均 P/R 的调和平均替代平均 F1。

## 实际资源

两组每次共享上限：**120 次模型 CLI 调用（含预留的最终回答一次）、40 次搜索 HTTP 请求、75 次读页 HTTP 尝试、3 次迭代、固定 n=2**。所有角色请求 `gpt-5.5`、medium reasoning。Full 按原 UQ 收益/成本选目标；Uniform 不读取显式 UQ 分数进行目标选择。两组保留 KG、图更新与引用，采用相同且不依赖 UQ 的停止规则；这是共享设置下的规划对照。

| 方法 | CLI 调用/次运行 | 搜索请求/次运行 | 读页尝试/次运行 | CLI 报告输入 token/次运行 | CLI 报告输出 token/次运行 |
|---|---:|---:|---:|---:|---:|
| Helicase | 111.65 | 29.65 | 70.20 | 1,298,758.03 | 114,831.10 |
| Uniform-planning KG | 112.93 | 30.60 | 70.10 | 1,315,249.70 | 112,689.85 |

正式研究共 **8,983 次 CLI 调用、2,410 次搜索、5,612 次读页尝试**。搜索均返回 HTTP 200；读页包含重定向、非 200 响应和网络错误，HTTP 200 也不等于内容已被成功解析或支持具体主张。四次试运行及新 key 预检另用 95 次搜索，共记录 2,505 次搜索请求；这不是服务账户余额或计费额度的独立证明。

**Token 仅为 CLI `turn.completed` 报告的用量，不严格匹配，也不视为独立核实的全部计费用量。** 缓存输入已包含于输入 token，不能再相加。CLI 配置虽然请求关闭重试，实际仍见过内部重连；模型上限单位是外层 CLI 调用，不是内部 HTTP 请求数。请求模型名已记录，后端具体权重快照未获独立确认。

评估阶段另有 **121 次不同 CLI 调用**：120 个最终任务记录，外加一次未采用的抽取补跑。按调用 ID 去重后，评估报告输入 1,767,130、输出 201,612 token。原采集器只汇总 120 个最终任务；本目录 `summary.json` 已纳入保留的失败尝试，并在 `original_collection_evaluation_usage` 中保留原口径。

## 评分协议及核对边界

使用作者确认的 `scpqa.jsonl` 与预先冻结的 `blind_direct_answers_v4` 参考卡片。完整新报告先不看 reference 抽取答案，再按题对四份匿名答案统一粒度，最后匹配固定 reference。程序从最大一对一匹配数计算 P/R/F1，结构代理项不进入主表。

80 份抽取、20 组规范化、20 组匹配均有最终有效记录。独立核对覆盖全部 80 次的匹配基数、P/R/F1、逐题均值、重复均值/样本 SD、配对 bootstrap 和研究资源台账。额外检查了此前关注的 Q64/Q73 及发生格式恢复的 Q69；这不等于全量独立人工语义裁决。

Q64 的新回答多为泛指电池材料或未证实的产品联系，reference 明确列出 4680、Powerwall、Megapack；Q73 的新回答多表示未能确认，reference 列出冰箱、冷柜、空调。两题各四次执行均未形成匹配。这里的低分反映本协议下的参考一致性，不能直接等同于现实事实错误。

固定协议仍有已披露的限制：Q63/Q65/Q68/Q72/Q75 的 reference 包含认知性回答，而 V4 抽取排除部分“没有公开确认”表述。本次保留这些题和原分母，未看到结果后删除题目或修改 reference。作者确认文件不代表 reference 的来源独立性或全部事实已独立核验。

## 异常及格式恢复

- **72 次完整、8 次部分完成**全部计入：Full 为 38/2，Uniform 为 34/6。每次都有最终报告；部分完成没有改成完整，也没有只统计成功子集。
- 研究阶段保留 3 次失败的模型 CLI 调用：两次含内容过滤重连事件，一次因日志内 Unicode 行分隔符触发冻结客户端解析错误。另有 10 条读页编码错误日志发生在模型派发前，不虚构成已调用模型的次数。预算拒绝及内部搜索 allowance 拒绝另列；它们不等于 Serper 额度耗尽。完整执行状态也不代表每个内部步骤成功。
- 第二次 Q61/Full 期间电脑合盖睡眠 759 秒，原调用恢复后成功；没有为此重跑，耗时分析需保留这项干扰。
- 第二次 Q69/Full 的抽取两次均把原文引用开头的 `the` 写成 `The`。两次原始失败响应、用量和哈希完整保留。对全部抽取适用同一项离线格式核对，实际仅该任务的两处引用需恢复：采用**最早原始响应**，仅恢复能唯一定位的 `The/the` 引用，答案标签、主张、状态、数量不变。名称变化、句中变化、歧义和实质改写仍拒绝。该步骤是**明确披露的冻结协议之外的格式恢复**，没有伪称原始响应直接通过。
- [格式恢复工具](../../quote_case_recovery.py) 与回归测试独立于冻结研究模块；研究代码、评分提示词、reference 和匹配规则没有改写。项目测试 229 passed、3 skipped；恢复后 79 份原成功抽取保持原字节。
